# 나이트 부대 배치 — 전장 퍼즐

1~4번 부대를 판에 배치하는 논리 퍼즐. 나이트 이동으로 닿는 칸은 서로 달라야 하고,
어느 방향으로도 같은 부대가 3칸 연속으로 늘어설 수 없다.

**기능** — 혼자 플레이 · 한 판에 힌트 5회 · 로그인 · 규격/난이도별 랭킹 · 최대 4인 실시간 대전

같은 저장소에 게임이 셋 있다 — **나이트 부대 배치**, **레이저 미로**, **타자 도장**(초등 한글 타자).

설계 문서: [DESIGN.md](DESIGN.md)

---

## 구성

정적 파일뿐이라 빌드 도구가 필요 없다.

```
index.html          셸 — 머리말 · 탭 · 오버레이
css/theme.css       색 토큰 · 지면 · 공통 컨트롤
css/board.css       3D 전장 판 · 부대 팔레트
css/app.css         탭 · 계정 · 랭킹 · 대전
js/config.js        ★ Supabase 설정을 여기에 넣는다
js/engine.js        퍼즐 생성 · 논리 솔버 (순수 계산, DOM 없음)
js/game.js          판 UI · 힌트 제한 · 타이머
js/ui.js            토스트 · 오버레이 · 탭 · 저장소
js/supabase.js      클라이언트 · 세션 · 동시접속 제한
js/auth.js          로그인 · 가입 · 계정 메뉴
js/rank.js          랭킹 보드 · 기록 등록
js/room.js          대전 로비 · 방 · 실시간 진행률
js/app.js           진입점
supabase/schema.sql DB 스키마 (한 번만 실행)

knight-troop-puzzle.html   분리 이전의 단일 파일 — 인터넷 없이 열리는 오프라인 버전
```

게임은 첫 화면(`index.html`)에서 고른다. 게임마다 페이지 하나와 폴더 하나를 쓴다.

```
laser.html          레이저 미로            js/laser/    data/laser-*.json
type.html           타자 도장              js/type/     data/type-words.json
```

`js/config.js`를 비워 두면 **혼자 플레이 모드**로 동작한다. 랭킹·대전 탭은 설정이 필요하다고
안내하고, 게임 자체는 완전히 정상으로 돌아간다.

## 온라인 기능 켜기 — Supabase

무료 티어로 충분하고 카드 등록이 필요 없다.

### 1. 프로젝트 만들기

[supabase.com](https://supabase.com) 에서 새 프로젝트를 만든다. 리전은 가까운 곳(예: Northeast Asia)으로.

### 2. 스키마 적용

대시보드 **SQL Editor** 에 [`supabase/schema.sql`](supabase/schema.sql) 전체를 붙여넣고 실행한다.
여러 번 실행해도 안전하다.

`schema.sql` 은 나이트 퍼즐에 필요한 것까지다. 뒤에 붙은 게임들은 패치로 나뉘어 있으므로
**`supabase/patch-*.sql` 을 번호 순서대로 이어서 실행한다.** 새 프로젝트든 예전 프로젝트든 같다.

| 파일 | 무엇 |
| --- | --- |
| `patch-01-session-token.sql` | 한 계정 동시접속 제한 |
| `patch-02-laser.sql` | 레이저 미로 — 등반 진행 |
| `patch-03-laser-versus.sql` | 레이저 미로 — 대전 점수·급수 |
| `patch-04-type.sql` | 타자 도장 — 단계 별·최고 기록 |
| `patch-05-type-write-duel.sql` | 타자 도장 — 아이가 쓴 글 보관·1:1 대결 |

패치를 건너뛰어도 나머지는 정상으로 돌고, 그 게임의 기록만 이 브라우저에 남는다.

### 3. 이메일 확인 끄기 ⚠️

**Authentication → Sign In / Providers → Email** 에서 **Confirm email 을 반드시 끈다.**

이 게임은 이메일을 받지 않고 아이디만 받는다. 내부적으로 `아이디@users.knight-puzzle.app`
형태의 주소를 만들어 Supabase Auth에 넘기는데, 확인 메일을 켜 두면 존재하지 않는 주소로
메일이 나가고 가입이 끝나지 않는다.

### 4. 키 넣기

**Project Settings → API** 에서 두 값을 복사해 `js/config.js` 에 넣는다.

```js
export const SUPABASE_URL = "https://xxxxxxxxxxxx.supabase.co";
export const SUPABASE_ANON_KEY = "eyJhbGciOi...";
```

`anon` 키는 공개용이라 저장소에 커밋해도 된다. 실제 권한은 DB의 RLS 정책과
`SECURITY DEFINER` 함수가 정한다. **`service_role` 키는 절대 넣지 말 것** — 그 키는
모든 정책을 우회한다.

커밋하고 푸시하면 랭킹과 대전이 켜진다.

## 알아두면 좋은 것

**무료 프로젝트는 오래 쓰지 않으면 일시정지된다.** 정지 중에는 로그인·랭킹·대전이 멈추고
혼자 플레이만 된다. 대시보드에서 수동으로 재개하면 되고, 방문이 뜸할 것 같으면
GitHub Actions 크론으로 하루 한 번 가벼운 요청을 보내 두면 된다.

**비밀번호는 복구할 수 없다.** 이메일을 받지 않기 때문이다. 나중에 선택 입력으로 이메일을
받으면 Supabase의 재설정 메일 기능을 그대로 켤 수 있다.

**기록 시간은 클라이언트가 보고한 값이다.** RLS가 막아 주는 것은 남의 이름으로 기록을
올리는 것과 남의 기록을 지우는 것이고, 자기 기록의 시간 자체는 개발자 도구로 위조할 수 있다.

**대전에서 상대에게 가는 정보는 채운 칸 수 하나뿐이다.** 판의 값이나 위치는 전송하지 않으므로
구조적으로 베낄 방법이 없다.

## 타자 도장

초등학생이 한글 타자를 처음 배우는 곳이다. 세 화면으로 되어 있다.

- **익히기** — 홈 위치 여덟 자리(`ㅁㄴㅇㄹ` · `ㅗㅓㅏㅣ`)에서 시작해 열 단계로 자판 전체를 익힌다.
- **낱말** — 아이가 고른 주제(공룡·우주·바다 …)의 낱말을 이어서 친다.
- **글쓰기** — 짧은 글을 그대로 옮겨 치고(베껴쓰기), 글감을 골라 자기 글을 쓴다(자유 작문).
- **성 지키기** — 낱말을 달고 오는 적을 쳐서 막는다. 표적은 가장 앞선 적으로 저절로 잡힌다.
- **대결** — 방을 만들어 여섯 자리 코드를 친구에게 알려 주면 1:1로 붙는다.

**자판을 직접 읽는다.** 글자 입력칸에 포커스를 주지 않아 브라우저의 한글 조합기가 끼어들지
않고, `js/type/hangul.js` 의 두벌식 조합기가 낱자를 직접 붙인다. 그래서

- 키보드가 **영문 상태여도 한글이 나온다** — 아이가 한/영 전환과 씨름하지 않아도 된다
- **낱자 하나하나를 채점**할 수 있어 "지금 이 자리를 틀렸다"를 그 자리에서 알려 준다
- 다음에 누를 자리와 **어느 손가락인지**를 화면 자판이 짚어 준다

대신 **물리 키보드가 필요하다.** 터치 기기로 열면 그렇게 안내한다.

**통과는 정확도로만 가른다**(90%). 손이 느린 아이가 한 단계에 갇혀 그만두지 않게 하려는
것이고, 빠른 것은 별 둘·셋으로 따로 갚는다. **틀린 자리는 넘어가지 않는다** — 대충 넘기고
뒤에서 고치는 버릇이 붙으면 자리를 영영 못 외우기 때문이다.

주제 낱말과 자리 진도가 부딪히는 곳은 규칙 하나로 푼다. 그 단계까지 배운 자리로 칠 수 있는
주제 낱말을 먼저 골라 넣고, 모자란 만큼을 음절로 채운다. 초반에는 걸리는 낱말이 거의 없어
저절로 음절 연습이 되고, 자리가 늘수록 아이가 고른 주제의 낱말이 스스로 섞여 들어온다.

### 글쓰기

베껴쓰기는 익히기·낱말과 같은 판을 쓴다 — 규칙이 같아야 아이가 헷갈리지 않는다.

자유 작문만 판이 다르다. 무엇을 쓸지 아이가 정하므로 맞고 틀림이 없고, 그래서
**틀린 자리를 막는 규칙이 여기서는 성립하지 않는다.** 대신 누른 대로 나오고,
글은 **끝에서만** 쓰고 지운다 — 가운데를 고치려면 커서 옮기기·선택·잘라내기가 딸려
오는데, 이제 자판을 외우는 아이에게는 그 전부가 방해다.

쓴 글은 **본인만 본다.** 남에게 보여 주는 길은 만들지 않았다. 이 브라우저에 남고,
로그인하면 서버와도 합쳐져 기기를 옮겨도 이어진다.

자유 작문 때문에 조합기가 **숫자줄과 문장부호 전체**를 받게 되었고, 화면 자판도
실제 배열로 늘어났다. 느낌표 하나를 못 받으면 "신난다!"에서 손이 멈추기 때문이다.

### 대결

**1:1 뿐이다.** 방을 만들면 여섯 자리 코드가 나오고, 친구가 그 코드로 들어온다.
겨루는 종목은 둘 — **글쓰기**(같은 글을 나란히, 먼저 끝낸 쪽이 승)와
**성 지키기**(똑같은 적이 같은 순서로, 먼저 다 막은 쪽이 승).

**상대를 방해하는 수단은 없다.** 두 사람에게 같은 판이 가고 빠르기로만 갈린다.
그래야 진 아이가 왜 졌는지 납득한다.

**급수(점수)는 두지 않았다.** 레이저 대전에는 있지만, 이 도장은 "정확도만 넘으면
통과, 못한다고 겁주지 않는다"를 원칙으로 잡았다. 지면 점수가 깎여 내려가는 장치는
그 원칙과 정면으로 부딪힌다. 몇 번 이기고 졌는지만 센다.

아직 없는 것 — **영타**. 한글 자리를 굳힌 뒤에 연다.

## 규칙

- 모든 칸에 1~4번 부대 중 하나가 들어간다
- 나이트 이동(직선 한 칸 + 이어서 대각선 한 칸)으로 닿는 두 칸은 같은 부대일 수 없다
- 가로·세로·대각선 어느 방향으로도 같은 부대가 3칸 연속으로 늘어설 수 없다

출제기는 정답지에서 칸을 지우되 **해당 난이도의 논리 솔버가 끝까지 푸는 경우에만** 지운
상태를 유지한다. 논리만으로 완주된다는 것은 해가 유일하다는 뜻이므로, 유일해와 풀이
가능성이 동시에 보장된다.
